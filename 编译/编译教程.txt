================================================================================
  Nepgear 内嵌 .chs 编译说明
  输入: Nepgear.chs  ->  输出: version.dll（补丁数据打包进 DLL）
================================================================================

【这套流程解决什么】

  普通构建出的代理 DLL 在运行时要读游戏目录里的 Nepgear.chs。
  走完这套流程后，.chs 会作为 RCDATA 资源写进 DLL，
  部署只需要 version.dll + Nepgear.ini，不必再带 .chs / .dat。

  产物固定为 version.dll：转发系统 version.dll 的 17 个 Ver* 导出，
  TargetName、dllmain.cpp 里选用的代理头、x64 汇编跳板都指向它。

  运行时查找顺序（Nepgear\hooks\vfs.cpp）：

    1. 游戏目录（或 [FileRedirect] RedirectFolder 指向的目录）里有 Nepgear.chs
       -> 用外部文件，换补丁不用重新编译
    2. 没有外部 .chs
       -> 用 DLL 里内嵌的资源
    3. 松散文件目录始终优先于归档（原有行为，未改动）


【启动弹窗：编进去还是彻底编掉】

  启动时那个「游玩通知」（补丁作者 + 声明）有两层开关：

    编译期  NEPGEAR_ENABLE_STARTUP_POPUP=0
            整段提示连同字符串一起编掉，DLL 里搜不到作者信息，
            连 MessageBoxW 调用都没有，体积也会小几百字节。
            默认是 1（保留弹窗）。

    运行期  Nepgear.ini -> [System] ShowStartupPopup=0
            代码还在，只是运行时跳过。改 ini 立刻生效，不用重新编译。

  编译期关闭的三种写法（任选其一）：

    一键脚本：
      python 编译\build_chs_embed.py Nepgear.chs x86 --no-popup

    build.bat 位置参数：
      build.bat x86 nopopup

    直接调 MSBuild：
      msbuild Nepgear.sln -p:Configuration=Release -p:Platform=Win32 -p:NepgearStartupPopup=0

  想恢复弹窗：去掉上述开关重新编译（build.bat x86 popup）。

  注意：这个开关会切到独立的中间目录
  （obj\<平台>\<配置>\popup0\ 与 popup1\），
  所以关掉/打开一定会真正重编 utils.cpp，不存在"改了宏但复用旧 obj"的老坑。


【准备工作】

  1. Visual Studio 2022，安装时勾选"使用 C++ 的桌面开发"
  2. Python 3.8+（安装时勾选 Add python.exe to PATH）
  3. 一个 Nepgear.chs —— 用 Packer.exe 从补丁文件夹打包得到


【方法一：一键脚本（推荐）】

  在项目根目录执行：

    python 编译\build_chs_embed.py Nepgear.chs x86

  第二个参数是架构：x86 / x64 / all，省略时默认 x86（多数 Galgame 是 32 位）。
  产物固定为 version.dll，形态固定为"预解压内嵌 + 未压缩"：
  每个条目先解成原始数据再打进资源，DLL 读归档时不再解压，PE 里也没有 UPX 段。
  没有更小体积的备选，工程里也不再有打包压缩这一步。

    产物：
      x86 -> Release\version.dll
      x64 -> x64\Release\version.dll

  常用写法：

    python 编译\build_chs_embed.py Nepgear.chs all
    python 编译\build_chs_embed.py D:\Games\某游戏\Nepgear.chs x86
    python 编译\build_chs_embed.py Nepgear.chs x86 --no-popup

  其它开关：

    --no-popup      不编译启动弹窗（等同 NEPGEAR_ENABLE_STARTUP_POPUP=0）
    --no-build      只生成资源，不编译
    --rebuild       强制全量重建（/t:Rebuild）
    --clean         删掉 chs_payload.rc / chs_payload.dat，之后构建不带内嵌


【方法二：手动三步】

  第 1 步：把 .chs 复制成资源输入文件

    copy /b Nepgear.chs Nepgear\chs_payload.dat

    （手动法内嵌的是原始 .chs，条目仍由 VFS 在运行时按需解压。要走
      "预解压内嵌"就用方法一，或用 decompress_chs.exe 先生成未压缩 .dat
      再复制成 chs_payload.dat。）
  第 2 步：在 Nepgear\ 下新建 chs_payload.rc，内容只有一行

    101 RCDATA "chs_payload.dat"

    （101 必须和 Nepgear\hooks\vfs.cpp 里的 NEPGEAR_CHS_RESOURCE_ID 一致。
      Nepgear.vcxproj 里该项带 Condition，只有 chs_payload.rc 存在时才编译它，
      所以没有资源的工程照旧能编。）

  第 3 步：编译

    build.bat x86 rebuild          -> Release\version.dll（未压缩）
    build.bat x86 nopopup          -> 同上，但去掉启动弹窗
    build.bat all rebuild          -> 两个架构

  build.bat 的位置参数可自由组合（架构 / popup|nopopup / rebuild / debug），
  顺序不限。
  想恢复"不带内嵌"的普通构建：删掉 Nepgear\chs_payload.rc 与 chs_payload.dat
  再重建，或直接 python 编译\build_chs_embed.py --clean。


【为什么用资源，而不是 C 数组】

  把 .dat 转成 chs_embed.h（一堆 0xNN 初始化列表）同样能内嵌，但代价很高：
  这套 .chs 是 8.9 MB，解压后 22 MB，转成 C 源码约 140 MB，cl.exe 直接报
  C1060"编译器的堆空间不足"，而且每次换包都要重新编译超大源文件。

  现在的做法是 rc.exe 把 .dat 原样放进 .rsrc，链接器合并进 DLL，
  运行时用 FindResourceW / LockResource 拿到只读指针：
  零拷贝、零编译开销、换包只重编资源并重链接。

  每个条目都先预解压再内嵌：读归档的整条路径都不再做 LZMS 解压。
  代价是资源从 8.9 MB 变成 22 MB，换来的是一整条读取路径不再有解压开销。

  解压本身走的是 Common\lzms_decode.h 里的内置解码器，而不是 cabinet.dll：
  Wine / Winlator 上那套压缩 API 是空壳（CreateDecompressor 直接返回成功，
  Decompress 只把输入拷回去），照搬系统 API 会一律报"LZMS 解压失败"。
  内置解码器优先不用，系统 API 解不出正确大小时自动接管。


【文件说明】

  编译\build_chs_embed.py   一键流程：生成资源 -> 调 build.bat
  编译\decompress_chs.cpp   LZMS 解压小工具（排查用）
  Common\lzms_decode.h      内置 LZMS 解码器（不依赖 cabinet.dll）
  编译\编译教程.txt         本文件

  Nepgear\chs_payload.dat   资源输入（生成物，不要提交）
  Nepgear\chs_payload.rc    资源脚本（生成物，不要提交）
  Nepgear\hooks\vfs.cpp     读取内嵌资源的代码
  Nepgear\ProxyVersion.h    version.dll 的导出/转发表


【想手工检查解压结果时】

  用 vcvarsall 初始化 x86 编译环境后：

    decompress_chs.exe Nepgear.chs Nepgear_raw.dat

  （脚本预解压时做的就是这件事，日常不需要单独跑。）


【怎么确认内嵌生效】

  Nepgear.ini 打开日志：

    [Debug]
    LogToFile=1

  启动游戏后看游戏目录下的 Nepgear.log：

    [VFS] Using embedded archive (9317317 bytes)
    [VFS] Initialized in Modern mode with 624 files (xx directories, embedded archive)

  如果显示 external archive，说明用的是游戏目录里那份 .chs，内嵌数据没被采用。


【注意事项】

  - 换包只需重跑脚本：脚本会 touch chs_payload.rc，MSBuild 只重编资源再链接，
    不会全量重建；要全量就加 --rebuild。
  - chs_payload.dat / chs_payload.rc 已写进 .gitignore，别把 8 MB 以上的二进制提交上去。
  - 产物约 24 MB（22 MB 解压后资源 + 代码），未压缩，这是交付形态本身。
  - 归档格式仍是 int32 字段，单条目上限 2 GB，条目数上限由 vfs 侧限制。
  - 关弹窗后别把 Nepgear.ini 里的 ShowStartupPopup 当唯一开关：那是运行时开关，
    编译期关掉才是真的把作者信息从 DLL 里删干净。


【部署】

  游戏主 EXE 所在目录\version.dll    <- 编译输出，架构必须与游戏进程一致
  游戏主 EXE 所在目录\Nepgear.ini    <- 配置，必须存为 UTF-16 LE
  （不需要 Nepgear.chs）
